# AGENTS.md

## Proyecto
Portfolio personal de Diego Molero Menéndez, desarrollador web / multiplataforma junior.

## Objetivo
Construir una web portfolio profesional, simple, moderna y atractiva que presente claramente:
- perfil profesional
- habilidades principales
- experiencia
- formación académica
- proyectos destacados
- contacto

La web debe servir como carta de presentación profesional y reforzar la imagen de un perfil junior con experiencia real, versátil, serio y con buena base técnica.

Actualmente participa en el desarrollo full stack de una intranet corporativa en Solarig para distintas áreas de negocio. Su formación incluye DAW, DAM y SMR. Tiene especial afinidad con Laravel, PHP, JavaScript, TypeScript, React, Inertia.js, bases de datos, Linux y tecnologías de infraestructura / sistemas. ## Stack obligatorio
- Laravel 13
- React
- Inertia.js

## Principios del proyecto
1. Simplicidad por encima de la complejidad
2. Diseño atractivo sin recargar
3. Código limpio y mantenible
4. Componentes reutilizables
5. Buena experiencia responsive
6. Accesibilidad básica bien resuelta
7. Buen rendimiento
8. Contenido honesto: no inventar experiencia ni métricas
9. Preparado para crecer con nuevos proyectos y secciones

## Objetivos de diseño
El portfolio debe transmitir:
- claridad
- profesionalidad
- modernidad
- cercanía
- potencial de crecimiento

Evitar:
- layouts excesivamente complejos
- estética artificial o demasiado “plantilla”
- animaciones invasivas
- bloques de texto demasiado densos
- barras de skill falsas o exageradas
- iconografía innecesaria sin valor informativo

## Dirección visual
La interfaz debe seguir una línea:
- minimalista
- elegante
- moderna
- con buena jerarquía visual
- con espacios en blanco bien usados
- con contrastes correctos
- con microinteracciones sutiles

## Arquitectura recomendada
Usar una landing page principal con secciones bien definidas:
- Hero
- Sobre mí
- Habilidades
- Experiencia
- Formación
- Proyectos
- Contacto

Si durante el desarrollo conviene separar alguna sección en páginas internas (por ejemplo, proyectos), hacerlo sin romper la experiencia principal de portfolio.

## Restricciones de contenido
- No inventar empresas, proyectos, estudios, certificaciones ni premios.
- No exagerar seniority.
- No mostrar métricas inventadas.
- Reescribir y mejorar el copy sí está permitido, siempre que no altere la veracidad del contenido.
- Si faltan textos concretos, proponer placeholders claramente identificados o pedir confirmación.

## UX/UI guidelines
- Priorizar legibilidad y escaneabilidad
- Evitar bloques largos de texto
- Usar tarjetas, grids y timelines si mejoran la comprensión
- Mantener CTAs claros
- Hacer scroll agradable y natural
- Cuidar mucho el estado responsive móvil
- Mantener consistencia visual entre secciones

## Componentización
Crear componentes reutilizables cuando tenga sentido, por ejemplo:
- Section
- SectionTitle
- Container
- Hero
- About
- SkillsGrid
- ExperienceTimeline
- EducationList
- ProjectsGrid
- ProjectCard
- ContactSection
- Footer

## Estilo de código
- Mantener estructura ordenada y semántica
- Usar nombres de componentes claros
- Evitar duplicación
- Separar contenido, layout y presentación cuando sea razonable
- Favorecer composición frente a complejidad innecesaria
- Documentar brevemente decisiones importantes si ayudan al mantenimiento

## Accesibilidad
- Usar HTML semántico
- Contraste suficiente
- Estados focus visibles
- Imágenes con alt si existen
- Navegación razonable por teclado
- Respetar jerarquía correcta de headings

## Rendimiento
- Evitar librerías pesadas si no aportan valor claro
- Minimizar animaciones costosas
- Optimizar imágenes
- Mantener bundle razonable
- No añadir dependencias por moda

## Copywriting
El tono textual debe ser:
- profesional
- natural
- claro
- directo
- actual

Evitar:
- frases demasiado genéricas
- lenguaje inflado
- claims grandilocuentes
- tecnicismo innecesario

## Modo de trabajo esperado del agente
Cuando se pida una mejora o nueva funcionalidad:
1. entender el objetivo
2. proponer la solución más simple que cumpla bien
3. respetar el stack y la dirección visual
4. no romper consistencia con el resto de la web
5. explicar brevemente decisiones relevantes
6. mantener fidelidad al perfil real del portfolio


Si hay dudas entre varias opciones de implementación, elige la más simple, mantenible y coherente con un portfolio personal profesional.
